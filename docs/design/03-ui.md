### 2.1 レイアウトモデル（純粋関数）

描画はすべて `src/components/chart/layout.ts` の `computeLayout()` の結果だけを使う。画面と PDF で同じ関数・同じ SVG 部品を使う（ARCHITECTURE「同じ座標系」）。

```ts
export interface LayoutInput {
  doc: GanttDocument; derived: DerivedIndex; wc: WorkCalendar;
  zoom: Zoom; collapsed: ReadonlySet<string>; valueColumn: "duration" | "hours";
  range?: { start: IsoDate; end: IsoDate };  // 省略時は §2.2 で計算
}
export interface RowLayout { taskId: string; index: number; rowNo: number; y: number; depth: number; isParent: boolean; collapsed: boolean; name: string; valueText: string }
export interface BarLayout { taskId: string; kind: "leaf" | "summary"; x: number; w: number; y: number; color: string; progress: number; progressText: string; resourceText: string; labelX: number }
export interface ArrowLayout { succId: string; predId: string; d: string; head: string /* polygon points */; violated: boolean }
export interface HeaderCell { x: number; w: number; label: string }
export interface NonWorkingBand { x: number; w: number }
export interface Layout {
  range: { start: IsoDate; end: IsoDate }; dayWidth: number;
  timelineWidth: number; bodyHeight: number;
  rows: RowLayout[]; bars: BarLayout[]; arrows: ArrowLayout[];
  headerTop: HeaderCell[]; headerBottom: HeaderCell[]; nonWorking: NonWorkingBand[];
  todayX: number | null;
}
export function computeLayout(input: LayoutInput, today: IsoDate): Layout;
export function xOfDate(layout, d: IsoDate): number; // diffDays(range.start, d) * dayWidth
export function dateAtX(layout, x: number): IsoDate; // floor
```

- `rowNo` は **全タスクの通し番号**（`derived.order` の index+1）。折りたたみに関係なく不変で、サイドパネルの先行タスク「#番号」・PDF とも一致する（隠れた行の番号は飛ぶ）。
- 本体の y 座標: 行 i（可視行 0 始まり）の上端 `y = i * ROW_HEIGHT`、中心 `y + 13`。ヘッダは別 SVG（§2.3）なので本体 y は 0 始まり。

### 2.2 タイムラインの表示範囲

ドキュメントの全タスク（折りたたみ無関係）の `minStart` / `maxEnd`（タスクが無ければ両方 today）から:

| zoom | range.start | range.end |
|---|---|---|
| day / week | `addDays(minStart, -7)` 以前の直近の**月曜** | `addDays(maxEnd, 28)` 以降の直近の**日曜** |
| month | `addDays(minStart, -7)` の月の 1 日 | `addDays(maxEnd, 60)` の月の末日 |

ドラッグ中はレイアウトの range を**ドラッグ開始時の値で固定**（プレビューで範囲が伸縮して画面が揺れるのを防ぐ）。確定後に再計算。

## 5. バーの描画（Timeline 本体）

### 5.1 リーフバー

- `x = xOfDate(start)`, `w = xOfDate(end) + dayWidth - x`（end 包含）。最小 `w = 2`。
- `y = rowY + 5`, 高さ 16, 角丸 3。
- 色 `c` = 色ラベルの色。無し/未知 id なら `#4A90D9`。
- 未進捗部: `fill=c, fill-opacity=0.35`。進捗部: 左から `w * progress / 100` を `fill=c` で重ねる（角丸は外枠の clipPath で）。
- 進捗テキスト `"{round(progress)}%"`（10px）をバー中央に。`w < 36` なら描かない。文字色は `progress >= 50 ? "#FFFFFF" : "#1F2937"`。
- 右に `resourceText`（resourceIds の名前を `", "` 連結、未知 id は除外）を `x + w + 6`、11px `#4B5563`。
- 選択中のタスクのバーは 2px `#1D4ED8` の外枠。

### 5.2 親（サマリー）バー（ブラケット型）

- 範囲は導出 start〜end。`y0 = rowY + 7`。
- 本体 `rect(x, y0, w, 6)`、`fill = 色ラベルの色 ?? "#374151"`。
- 両端の下向きの爪: 左 `polygon (x,y0+6) (x+7,y0+6) (x,y0+12)`、右 `polygon (x+w,y0+6) (x+w-7,y0+6) (x+w,y0+12)`。
- 進捗: 本体の上に `rect(x, y0, w*progress/100, 6)` を `fill-opacity 1`、本体側は `fill-opacity 0.45`。
- ラベル: `x + w + 6` に `"{round(progress)}%"`、続けて（8px 空けて）resourceText。11px。
- 折りたたまれた親も同じ描画。

### 5.3 依存矢印

対象: 全依存。端点のタスクが折りたたみで不可視なら、**最も近い可視の祖先**の行・バーに置き換える。両端が同じ行になったら描かない。

```
x1 = 先行バーの右端（x + w）, y1 = 先行行の中心
x2 = 後続バーの左端（x）,     y2 = 後続行の中心
G  = ARROW_GAP (8)
if x2 - x1 >= 2G:
  d = M x1 y1 H (x1+G) V y2 H x2
else:
  yMid = (y2 > y1) ? 後続行の上端 : 後続行の下端      // 行の境界線上を通す
  d = M x1 y1 H (x1+G) V yMid H (x2-G) V y2 H x2
head = "x2,y2 (x2-6),(y2-3.5) (x2-6),(y2+3.5)"      // 右向き三角
```

- 線 1.2px `#6B7280`、`fill:none`。違反中（`findViolations` に含まれる）は `#DC2626`。選択中タスクの先行/後続の矢印は `#1D4ED8`。
- クリック判定用に同じ `d` で透明 8px の線を重ねる。クリックで矢印を選択（`selectedDependency = {succId, predId}`、太さ 2px）。Delete で `removeDependency`。
- 描画順: 非稼働帯 → 罫線 → 矢印 → バー → ラベル（矢印をバーの下に）。

## 6. ドラッグ操作

### 6.1 ヒット判定（pointerdown 時、ボタン 0 のみ）

| 対象 | 領域 | モード |
|---|---|---|
| リーフバー（`w >= 24`） | 左端から 6px | `resizeStart` |
| リーフバー（`w >= 24`） | 右端から 6px | `resizeEnd` |
| リーフバー（`w < 24`） | 右端から 4px | `resizeEnd`（`resizeStart` 無し） |
| リーフバー | 上記以外 | `move` |
| 親バー | 全体（爪を含む） | `move`（子を一括移動） |
| リンクハンドル | ホバー中のバー右端の外 `cx = x+w+8, cy = 行中心, r = 4` の円（ホバー中のみ表示、判定半径 6） | `link` |

カーソル: `move` = `grab`（ドラッグ中 `grabbing`）、resize = `ew-resize`、link = `crosshair`。

### 6.2 状態遷移

```
idle
 └ pointerdown(bar) ─→ pressed { taskId, mode, startX(コンテンツ座標), baseDoc = store.doc, baseRange }
                       ・選択を taskId に、setPointerCapture
pressed
 ├ pointermove: |dx| >= 3px ─→ dragging
 └ pointerup ─→ idle（クリック扱い：選択のみ）
dragging
 ├ pointermove: delta = Math.round(dx / dayWidth)
 │    delta が前回と異なれば:
 │      cmd = move:        { moveTask, id, deltaDays: delta }
 │            resizeEnd:   { resizeTaskEnd, id, newEnd: addDays(base.end, delta) }
 │            resizeStart: { resizeTaskStart, id, newStart: addDays(base.start, delta) }
 │      r = executeCommand(baseDoc, cmd, ctx)
 │      r.ok なら store.setPreview(r.doc)、NG なら直前のプレビューを維持
 │    ツールチップ: 新しい開始〜終了と期間（例「5/24 – 5/26 (3d)」）をポインタ右上に表示
 ├ pointerup ─→ delta != 0 なら store.dispatch(cmd)（= 1 Undo 単位）、clearPreview → idle
 ├ Escape / pointercancel / lostpointercapture ─→ clearPreview → idle（何も確定しない）
link モード（pressed から 3px 以上動いたら linking）
 ├ pointermove: 起点からポインタまで破線（`stroke-dasharray 4 3`）を描く。ポインタ下のバーをハイライト（`canAddDependency(doc, target, source)` が NG のバーは赤枠）
 └ pointerup: ポインタ下にバーがあれば dispatch({ addDependency, succId: target, predId: source })。NG ならトースト（`error.engine.<code>`）
```

- `dx` はコンテンツ座標（`clientX - scrollContainer.left + scrollLeft`）の差で計算し、自動スクロール分も反映する。
- 自動スクロール: ドラッグ中ポインタがタイムライン可視領域の左右 40px 以内なら、`requestAnimationFrame` ごとに 10px スクロールし、pointermove と同じ計算を行う。
- プレビュー中は `store.preview` を描画に使う（`doc` は不変）。ドラッグ中はキーボードショートカット（Escape 以外）を無視。
- dispatch 時、ストアの `doc` は `baseDoc` と同一（ドラッグ中は他の変更が入らない）なので、確定結果はプレビューと一致する。

## 7. インライン編集

`InlineEditor` は grid-body 上に `position:absolute` の `<input>` を 1 つ置く（行 y、列 x、幅は列幅、高さ 24）。

| 対象 | 開始 | 確定 | 取消 |
|---|---|---|---|
| 名前 | 選択済み行の名前クリック / 名前ダブルクリック / F2 / `addTask` 直後（`editName`） | Enter・フォーカス喪失 → 変更があれば `setName`。Tab / Shift+Tab → `setName` 確定後に `indent` / `outdent`（編集は終了） | Escape |
| 期間（リーフ） | 値列ダブルクリック | Enter・blur → `parseDuration`。null なら入力欄を赤枠にして編集継続（blur の場合は破棄）。値があれば `setDuration` | Escape |
| 工数（リーフ） | 値列ダブルクリック | 空なら `setHours(null)`、0 以上の数値なら `setHours(n)`、それ以外は赤枠で継続 | Escape |

- 開始時は全選択。IME 変換中（`isComposing`）の Enter は確定に使わない。
- 編集中は行操作のショートカット（§8.2 の「編集外のみ」）は無効。

### 8.2 キーボードショートカット

`Mod` = macOS は Cmd、Windows は Ctrl。**ファイル系と Undo/Redo はネイティブメニューのアクセラレータ**で受け（04-backend §7）、`menu-action` イベントで処理する。それ以外は `window` の `keydown` で処理する。

| キー | 動作 | 受け口 | 範囲 |
|---|---|---|---|
| Mod+N | 新規 | メニュー | 常時 |
| Mod+O | 開く | メニュー | 常時 |
| Mod+S | 保存 | メニュー | 常時 |
| Mod+Shift+S | 名前を付けて保存 | メニュー | 常時 |
| Mod+Shift+E | PDF 出力 | メニュー | 常時 |
| Mod+Z | 元に戻す（入力欄にフォーカス中は `document.execCommand("undo")`） | メニュー | 常時 |
| Mod+Shift+Z（Windows は Ctrl+Y も） | やり直し（入力欄では `execCommand("redo")`） | メニュー | 常時 |
| Enter | 選択行の下にタスク追加（未選択ならルート末尾） | keydown | 編集外のみ |
| F2 | 名前編集 | keydown | 編集外のみ |
| Delete / Backspace | 選択タスク削除（矢印選択中は依存削除）。子を持つ親は確認ダイアログ（§11.4） | keydown | 編集外のみ |
| Tab / Shift+Tab | インデント / アウトデント | keydown | 編集外のみ（編集中は §7） |
| ↑ / ↓ | 前 / 次の可視行を選択 | keydown | 編集外のみ |
| ← / → | 親を折りたたむ / 展開（リーフで ← は親を選択） | keydown | 編集外のみ |
| Alt+↑ / Alt+↓ | 上へ / 下へ移動 | keydown | 編集外のみ |
| Mod+D | 複製 | keydown | 編集外のみ |
| Mod+1 / 2 / 3 | ズーム 日 / 週 / 月 | keydown | 編集外のみ |
| Escape | ドラッグ取消 → 編集取消 → 矢印選択解除 の順に 1 つ | keydown | 常時 |

「編集外」= フォーカスが `input, textarea, select, [contenteditable]` でない。keydown で処理したら `preventDefault()`（Tab のフォーカス移動を防ぐ）。

### 8.3 ズーム切替

ズーム変更時、変更前にビューポート左端にあった日付 `d = dateAtX(scrollLeft)` を記録し、変更後 `scrollLeft = xOfDate(d)` にする（表示位置を保つ）。ファイルを開いた直後は `scrollLeft = xOfDate(minStart) - dayWidth`。

## 11. ダイアログ

すべて React のモーダル（`src/components/dialogs/`）。ネイティブダイアログはファイル選択（plugin-dialog の open/save）のみ。モーダル表示中はショートカット無効（Escape = キャンセル）。

### 11.1 SchemaErrorDialog（開けないファイル）

- タイトル「ファイルを開けません」、ファイルパス。
- 一覧（最大 200 件表示、超過は「ほか n 件」）: 各行 `path`（等幅）＋メッセージ。メッセージは `error.schema.<kind>` / `error.load.<code>` を params で埋める。該当キーが無い kind は Rust が返した英語メッセージをそのまま表示。
- ボタン: 「コピー」（全件をテキストでクリップボードへ）、「閉じる」。
- 対象エラー: `PARSE_ERROR`（行・列）、`UNSUPPORTED_VERSION`、`SCHEMA_INVALID`（一覧）、エンジンの意味検証エラー（01-data-model §3）、`IO_ERROR`。

### 11.2 ExternalChangeDialog（`file-changed-externally` 受信時）

| 状況 | 文言 | ボタン |
|---|---|---|
| 変更・未保存なし | 「ファイルが外部で変更されました。再読み込みしますか？」 | 再読み込み / 無視 |
| 変更・未保存あり | 「ファイルが外部で変更されました。未保存の変更があります。」 | 再読み込み（変更を破棄）/ 上書き保存 / 後で |
| 削除・移動 | 「ファイルが削除または移動されました。」 | 名前を付けて保存 / 閉じる（ダイアログのみ） |

- 再読み込み: `open_file` を再実行して置換。Undo 履歴はクリア、dirty 解除。失敗（スキーマ違反等）なら SchemaErrorDialog を出し現在の内容を保持。
- 上書き保存: 通常の保存。
- 無視 / 後で: 何もしない（次の外部変更で再度通知）。表示中に追加の通知が来ても同じダイアログを 1 つだけ表示。

### 11.3 UnsavedCloseDialog（未保存で閉じる）

`getCurrentWindow().onCloseRequested` で dirty なら `preventDefault` して表示。「"{name}" への変更を保存しますか？」→ 保存（成功したら閉じる、Save As をキャンセルしたら閉じない）/ 保存しない（閉じる）/ キャンセル。

### 11.4 ConfirmDialog（汎用）

子を持つ親の削除（「"{name}" と子タスク {count} 件を削除します」）、使用中リソース/ラベルの削除。ボタン: 削除 / キャンセル。

### 11.5 読み込み警告

`open_file` の warnings とエンジンの warnings が 1 件以上なら、チャート上部に黄色の帯（高さ 28）「読み込み時の警告が {count} 件あります [詳細] [×]」。詳細で一覧ダイアログ（SchemaErrorDialog と同じ見た目、タイトル「読み込み時の警告」）。

### 11.6 Toast

右下に 3 秒表示（エラーは赤、情報は灰）。エンジンのコマンドエラー（`error.engine.<CODE>`）、保存完了（「保存しました」）、PDF 出力完了（「PDF を保存しました」＋パス）に使う。

## 12. PDF 出力（フロント側）

1. `Mod+Shift+E` / ツールバー → `composeExportSvg(state)`（`src/export/composeSvg.ts`）。
2. `invoke("export_pdf", { svg, options })`（04-backend §4）。戻り値が null（キャンセル）なら何もしない。成功でトースト。
3. 処理中はツールバーの PDF ボタンをスピナー表示・無効化。

### 12.1 SVG の合成

- 画面と同じ `computeLayout`（現在の zoom・折りたたみ・valueColumn を反映）と同じ SVG 部品（`GridHeader` 等は `mode: "screen" | "export"` を受ける）を使い、`react-dom/server` の `renderToStaticMarkup` で文字列化する。
- 1 枚の SVG:

```
<svg xmlns="http://www.w3.org/2000/svg" width=W height=H viewBox="0 0 W H" font-family="Noto Sans JP">
  <rect width=W height=H fill="#FFFFFF"/>
  <g> タイトル帯 (x 0..330, 高さ 40): プロジェクト名 14px bold / 「期間 2023/05/22 – 2023/06/02 ・ 出力日 2026/10/22」10px </g>
  <g transform="translate(0,40)">     Grid ヘッダ </g>
  <g transform="translate(330,40)">   Timeline ヘッダ </g>
  <g transform="translate(0,88)">     Grid 本体 </g>
  <g transform="translate(330,88)">   Timeline 本体 </g>
</svg>
W = 330 + timelineWidth,  H = 40 + 48 + 可視行数 × 26
```

- export モードの差分: 選択・ホバー・リンクハンドル・today 線・ツールチップを描かない。違反矢印の赤は描く。テキストはすべて `font-family="Noto Sans JP"`（同梱フォント。04-backend §4.2）。`font-weight` は 400 / 700 のみ使用。
- タイトル帯は左 330px 内にのみ描く（PDF の横分割で左 330px を各ページに繰り返すため。§04-backend §4.3）。
- 外部参照（画像・`<use href="外部">`・CSS）を使わない。色は `#RRGGBB`、不透明度は `fill-opacity` 属性で指定（`rgba()` を使わない）。
- `options = { pageSize: "A3", orientation: "landscape", frozenWidth: 330, defaultFileName: "<ファイル名>.pdf" }`。

## 14. ファイル操作とウィンドウ

- ウィンドウタイトル: `{dirty ? "● " : ""}{ファイル名 ?? t("app.untitled")} — json-gantt`（`getCurrentWindow().setTitle`）。
- 新規（Mod+N）: 現在のウィンドウにドキュメントが無ければその場で `createEmptyDocument({ projectName: t("project.defaultName") })`。あれば `new_window(null, blank: true)`（04-backend §2）で `index.html?new=1` の新しいウィンドウを開く。起動時に `location.search` が `new=1` なら、そのウィンドウは `take_pending_open` を呼ばずに `newDocument()` でその場で新規作成する。
- 開く（Mod+O）: plugin-dialog `open({ filters: [{ name: "JSON", extensions: ["json"] }] })`。現在のウィンドウにドキュメントが無ければその場で、あれば新しいウィンドウで開く（1 ウィンドウ = 1 ファイル）。既に別ウィンドウで開いているパスなら、そのウィンドウを前面に出す（04-backend §2 `open_in_window`）。
- 保存（Mod+S）: パスがあれば `save_file`、無ければ Save As。Save As: plugin-dialog `save({ defaultPath: "<project.name>.json" })` → `save_file` → `watch_file(新パス)` → `add_recent_file`。
- 開いたら `watch_file(path)`、`add_recent_file(path)`。ウィンドウを閉じるとき `unwatch_file`。
- D&D: `getCurrentWebview().onDragDropEvent` の `drop` で最初の `.json` パスを「開く」と同じ規則で開く。ドラッグ中（`over`）はチャート全体に半透明の青い枠を表示。
- 起動引数・Finder からのオープン: Rust が `open-file-requested` を発火（04-backend §6）→ 同じ「開く」処理。

## 15. ストア（`src/store/`）

```ts
interface AppState {
  filePath: string | null;
  doc: GanttDocument | null;
  preview: GanttDocument | null;          // ドラッグ中のみ
  undo: UndoEntry[]; redo: UndoEntry[];   // UndoEntry = { id: number; patches; inversePatches; label }
  savedUndoId: number | null;             // 保存時点の undo 先頭 id（空なら null）
  viewDirty: boolean;
  selectedId: string | null;
  selectedDependency: { succId: string; predId: string } | null;
  editing: { taskId: string; field: "name" | "duration" | "hours" } | null;
  valueColumn: "duration" | "hours";
  sidePanelOpen: boolean; sidePanelTab: "project" | "tasks";
  loadWarnings: LoadIssue[];
  // actions
  loadDocument(path: string | null, doc: GanttDocument, warnings: LoadIssue[]): void; // 履歴クリア
  dispatch(cmd: Command): CommandResult;   // 成功かつ patches 非空なら undo に積み redo をクリア
  undo(): void; redo(): void;              // applyPatches
  setPreview(doc): void; clearPreview(): void;
  setZoom(z: Zoom): void; toggleCollapsed(id): void; expandAll(): void; collapseAll(): void; // view 変更: viewDirty = true、Undo 対象外
  markSaved(path: string): void;           // savedUndoId = 現在の undo 先頭 id, viewDirty = false
}
// セレクタ（メモ化）
isDirty = (undo 先頭 id ?? null) !== savedUndoId || viewDirty
displayDoc = preview ?? doc
derived = deriveAll(displayDoc, wc)       // displayDoc が変わったときのみ再計算
wc = compileCalendar(displayDoc.project.calendar)
```

- `dispatch` は `executeCommand(doc, cmd, ctx)`。`ctx = { today: todayIso(), newId, defaultTaskName: t("task.defaultName") }`。結果の `selection` / `editName` / `reveal` を UI 状態に反映（reveal は `revealTask` で view を変更 → viewDirty）。
- `undo()` 後の選択: 選択中 id が存在しなくなったら null。
- Undo 上限 200（古いものから捨てる。捨てた結果 `savedUndoId` に到達不能になっても isDirty の式はそのまま正しい）。
